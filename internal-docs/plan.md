# Implementation Plan — Phase/Task Journal

> Trimmed descendant of the original `mlops-methane-detection-plan.md` (Sections 1, 2, 4, 5, 9 — project context, infrastructure overview, architecture diagram, phase task list, and agent-prompt hints). Resolved-task bug-fix narratives are compressed to one-line summaries here — see git history / commit messages for full blow-by-blow if ever needed. Open-decision rationale lives in [decisions.md](decisions.md); the task-status table and completion checklist live in [status.md](status.md).

**Project**: Semantic Segmentation of Methane Plumes using CNN on Hyperspectral Imagery (Master's Final Project). Base dataset: STARCOP (SpaceML/ESA — AVIRIS-NG). Architecture reference: [spaceml-org/STARCOP](https://github.com/spaceml-org/STARCOP).

**Primary goal**: a reproducible, monitored, continuously-improvable ML system — demonstrating production-grade ML engineering, not just model performance. See `docs/methodology.md` (public) for the model-first framing; this file is the operational journal behind it.

**Foundational decisions** (2026-07-06): STARCOP embedded as a git submodule at `vendor/starcop/`, pinned upstream commit, never edited (composition-only — see `docs/pipeline/overview.md`). Two isolated `uv` environments: Environment A (`vendor/starcop/.venv`, Python 3.10, torch 1.13.1 — original STARCOP stack, reference-only) and Environment B (`.venv` at root, Python 3.12, torch ≥2.5 — active development).

---

## Infrastructure Overview

**Compute**: Desktop (RTX 5070, Windows 11 + WSL2/Arch, undecided — D-07) · MacBook M4 Pro (MPS) · Hostinger KVM 4 VPS (4 vCPU/16GB, Coolify-managed, no GPU — hosts all persistent services) · Google Colab (free tier, for large runs when local GPU is insufficient).

**VPS services** (all Coolify-managed Docker Compose stacks, each its own `deploy/<name>/{docker-compose.yml,.env.example,README.md}`): MLflow (experiment tracking + registry), Prefect (orchestration), BentoML (serving API), Grafana + Prometheus (monitoring/alerting).

**Storage**: raw STARCOP → Google Drive (DVC remote, dedicated OAuth client); processed datasets → same, DVC-tracked; model artifacts → MLflow artifact store (Backblaze B2, S3-compatible); Docker images → `ghcr.io`; code → GitHub (public).

**Architecture** (data → training → CI/CD → serving → monitoring → retraining, closing the loop back to training):

```
Google Drive (raw STARCOP) → DVC pipeline (normalize → split → patch_extract → stats → coordinates)
  → versioned splits → training (RTX 5070 / M4 Pro MPS / Colab) → STARCOP U-Net (fine-tune/variants)
  → MLflow (tracking → registry) → CI/CD gate (GitHub Actions: test → metrics gate → SemVer/CHANGELOG
  → Docker build → ghcr.io → Coolify deploy) → BentoML REST API → Prometheus/Grafana (drift, latency,
  error rate, spectral stats) → Prefect retraining loop (trigger → DVC pull → train → registry →
  gate → redeploy) → back into training
```

Full diagram: `docs/pipeline/overview.md` (Mermaid).

Diverges from spec: not gated on CI passing (`tests.yml`) — only serialized against it via a shared concurrency group, so a release can still be cut on a push whose tests are still running or later fail. `secrets.RELEASE_TOKEN` (admin PAT) needed since `main` is branch-protected and the default `GITHUB_TOKEN` can't push the version-bump commit.

Coolify deploy webhook needs **two** secrets, not one — see [decisions.md](decisions.md) / `docs/pipeline/serving.md` for the full step-by-step (`COOLIFY_WEBHOOK_URL` + a separate `deploy`-scoped `COOLIFY_TOKEN`). ## Phase 6 — Monitoring & Drift Detection

- **TASK-6.1 — Deploy Prometheus + Grafana** ✅ 2026-08-16. `deploy/monitoring/` (both services in one compose, mirroring the mlflow/postgres pairing). Scrapes the public HTTPS `/metrics` endpoint directly (not an internal Coolify network) — deliberate trade-off: `/metrics` has no auth, request counts/latencies become publicly readable; acceptable for this project's threat model, revisit if that changes. Alert notification channel: Pushover (native Grafana contact-point type, no SMTP needed — reuses the account already wired into Coolify's own deploy notifications). Added a custom `methane_prediction_total{result=...}` counter (BentoML's built-in instrumentation has no predicted-class label) — used `prometheus_client.Counter` directly with deferred construction, not the deprecated `bentoml.metrics` shim (which risks registering against a registry the real multiprocess `/metrics` collector never reads).
  - **7 real bugs, all fixed**: Coolify's file-vs-directory bind-mount bug (a bind-mounted file source that hasn't been staged gets auto-created as an empty directory — fixed by `COPY`-ing config into the image at build time instead of bind-mounting, since Coolify never syncs git-repo files into bind mounts at all); GHCR package never linked to the repo's `GITHUB_TOKEN` (denied `write_package` — fixed by granting Actions write access under the package's Manage Actions access); Coolify webhook unreachable from GitHub-hosted runner IPs (firewall/WAF in front of Coolify — worked around with a manual redeploy, not fixed properly); Restart ≠ Redeploy (Restart doesn't pull a new image even with `pull_policy: always`); stale `IMAGE_TAG=bootstrap` left over from TASK-5.2's bootstrap; wrong Pushover credentials (Application token vs. account User Key confused). Fully proven live: 301 real `/predict` requests populate all 4 dashboard panels, drift alert fired `[FIRING:4]` and delivered a real Pushover notification.
- **TASK-6.2 — Implement Input Data Drift Detection** ✅ 2026-08-16. Pure code addition on TASK-6.1's stack (no new infra) — rolling per-band mean/std (`collections.deque(maxlen=100)`, in-memory, per-process, resets on redeploy) vs. `starcop_raw`'s baseline (not `starcop_mini` — mini is curated toward plume-heavy scenes, would bias detection toward flagging typical traffic as anomalous), closed-form Gaussian KL divergence (`src/serving/drift.py`), threshold 0.5, exposed as `methane_band_kl_divergence{band=...}`. Band names aren't retained on the loaded model object at runtime — added `src/serving/band_baseline.py` mapping `MODEL_NAME` → band names + baseline stats.
  - **3 bugs found by code review before deploy**: baseline was pixel-level mean/std (dominated by sharp near-plume spikes) but the rolling window aggregates per-request spatial means — recomputed from the real 141,219-patch dataset as mean/std **of per-patch means** instead (`mag1c`'s baseline std dropped 310.13→37.72); concurrent `/predict` requests mutate the same deque across threads (BentoML dispatches sync handlers via `run_in_threadpool`) — fixed with a `threading.Lock`; the gauge was publishing before the rolling window had enough samples to estimate sigma meaningfully — gated on reaching the full 100-sample window. Live-validated: synthetic out-of-distribution requests produced elevated divergence (17–24 vs. the 0.5 threshold), alert fired `[FIRING:4]`, real Pushover notification delivered.
